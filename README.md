# githubio_book

DokuWiki 문서 또는 마크다운 폴더를 [VitePress](https://vitepress.dev) 정적 사이트로 변환해
GitHub Pages에 올리는 도구. 사이트 구조는 **서재 → 책 → 대분류 → 소주제 → 글** 4단계이고,
책이 몇 권이든 자동으로 늘어난다.

## 처음 쓰기

**`update.bat`** 을 더블클릭하면 창이 하나 열린다. 처음에는 **설정 마법사**가 한 단계씩 안내한다.

1. **글이 있는 곳** — 도쿠위키 또는 마크다운 폴더를 고른다.
2. **프로그램 확인** — git, pandoc(도쿠위키일 때)이 있는지 확인하고, 없으면 설치 페이지를 열어 준다.
   git 이 "누가 올렸는지" 알 수 있게 이름·이메일을 한 번 묻는다.
3. **GitHub 준비** — GitHub 아이디만 적으면 저장소 이름(`아이디.github.io`)과 주소가 자동으로 정해진다.
   가입 / 저장소 만들기 / Pages 설정 페이지를 버튼으로 열어 주고, **연결 확인**으로 마무리한다.
   (저장소는 Public 으로 만들고 README 등은 체크하지 않는다. Pages 의 Source 는 **GitHub Actions**.)
4. **사이트 이름** — 제목과 한 줄 소개.
5. **끝** — 저장한다.

이후에는 같은 창에서 **[▶ 사이트에 올리기]** 를 누르면 변환 + commit + push 가 진행되고, 진행 상황이
창 안의 로그에 나온다. 1~2분 뒤 사이트에 반영된다.
(처음 push 때 git 이 브라우저로 GitHub 로그인을 물어본다. 비밀번호/토큰은 이 도구가 저장하지 않는다.)

창의 다른 버튼: **[설정]**(전체 설정 창, 안에서 마법사를 다시 열 수도 있다), **[설정 초기화]**,
**[내 사이트 열기]**, **[올라가는 중인지 보기]**(GitHub Actions 진행 화면).

**[설정 초기화]** 는 이 컴퓨터 설정(`config.json`)과 사이트 정보(`site.json`)를 처음 상태로 되돌리고
마법사를 다시 연다. 지우기 전에 현재 설정을 `.settings_backup/날짜_시각/` 에 복사해 두므로, 되돌리려면
그 안의 파일을 폴더 맨 위로 복사하면 된다. 올려 둔 사이트와 글 원본은 건드리지 않는다.

### 이미 책이 올라가 있는 저장소에 올릴 때

저장소에 이 폴더에 없는 내용이 있으면 push 가 거절된다. 이때 어떤 책이 사라지는지 보여 주고
**"GitHub의 기존 내용을 지우고 덮어쓸까요?"** 를 물어본다. `예`를 누르면 GitHub 쪽이 이 폴더 내용으로
바뀐다(되돌릴 수 없으니 지켜야 할 책의 소스가 있는지 먼저 확인한다).

## 입력 소스 (설정에서 선택, 둘 다 켜면 함께 빌드)

| 소스 | 폴더 규칙 |
|---|---|
| **도쿠위키 → 마크다운** | 설정의 **책 폴더**(도쿠위키 `pages` 안의 폴더) 안의 `.txt` 하나 = 책 하나. `pages` 루트는 경로에서 자동으로 찾는다. 파일 안에서 `======` 대분류 / `=====` 소주제 / `====` 글 + `{{page>ns:id}}` 참조. pandoc 필요. |
| **마크다운 → 마크다운** | 마크다운 폴더 안의 **하위 폴더 하나 = 책 하나**. 그 안의 폴더 = 장, 그 안의 폴더 = 소주제, `.md` = 글. 폴더 밖의 `.md`는 한 페이지짜리 책. |

도쿠위키 세부:
- 파일 맨 위의 `====== 책 제목 ======` 처럼 **하위 제목 전체를 감싸는 제목 하나뿐**이면 그 제목은 건너뛴다
  (그대로 두면 책 이름과 같은 대분류가 하나 더 생겨 한 번 더 눌러야 한다).
- 제목에 `:` 같은 파일 이름에 못 쓰는 글자가 있으면 폴더/링크에서는 `-` 로 바뀐다. 화면에 보이는 제목은 그대로다.

마크다운 소스 세부:
- 이름 앞의 `01 `, `02_` 는 순서에만 쓰이고 제목에서는 빠진다.
- 노트 맨 위 `title:` (YAML frontmatter)가 있으면 그것을 글 제목으로 쓴다.
- 이미지 `![](img/a.png)` 와 Obsidian식 `![[a.png]]` 는 자동으로 사이트에 복사된다.
- 점(`.`)이나 밑줄(`_`)로 시작하는 파일/폴더는 무시한다.
- 4단계보다 깊은 폴더는 "폴더 - 글" 제목으로 펼쳐진다.

책을 지우려면 소스 파일/폴더만 지우면 된다 (다음 빌드에서 산출물도 정리됨).
반대로 **소스가 등록되어 있지 않은 책은 다음 빌드에서 사이트에서 사라진다**는 점에 주의한다.

## 댓글 (giscus, 선택)

[설정]의 "댓글" 항목에서 켠다. 순서:

1. GitHub 에서 **giscus 앱 설치**(내 사이트 저장소 선택)와 저장소 **Discussions 켜기** — 설정 창의 버튼이 해당 페이지를 열어 준다.
2. [giscus.app](https://giscus.app/ko) 의 "저장소" 칸에 `아이디/저장소이름` 형태로 쓴다(`https://github.com/` 나 `.git` 은 붙이지 않는다).
3. 맨 아래 생성된 `<script …>` 코드를 설정 창에 통째로 붙여넣고 **[값 자동 입력]**.

주의: 업로드용 "저장소 주소"는 `https://github.com/아이디/저장소이름.git`(전체 주소), 댓글의 "댓글 저장소"는 `아이디/저장소이름` 으로 형식이 다르다.

## 설정 파일 (설정 창이 만들어 준다)

- `config.json` — 이 컴퓨터 전용(경로, pandoc, 자동 push 여부). **git에 올라가지 않는다.**
- `site.json` — 사이트 제목/소개/언어/댓글(giscus). 저장소에 함께 올라가고 GitHub Actions 빌드도 읽는다.

## 구조

- `update.bat` — 메인 창(`tools/app.py`)을 연다. 올리기와 설정이 한 창에 있다.
- `tools/app.py` — 메인 창. 변환/업로드 스크립트를 순서대로 실행하고 로그를 보여 준다.
- `tools/wizard.py` — 처음 설정 마법사. `tools/settings_gui.py` — 전체 설정 창. `tools/config.py` — 설정 읽기/쓰기.
- `tools/remote_check.py` — GitHub 저장소 주소 검사("연결 확인").
- `tools/build_books.py` — 핵심 변환기. `tools/markdown_source.py` — 마크다운 폴더를 변환기 입력으로 바꾸는 어댑터.
- `tools/build_library.py` — 서재 첫 페이지(`docs/index.md`) 생성. `tools/publish.py` — commit + push.
- `tools/make_release.py` — 책·개인 설정을 뺀 도구 사본을 배포용 저장소에 올린다.
- `docs/.vitepress/config.mjs` — `site.json`/`books.json`/`sidebar.json`으로 nav·사이드바 구성.
- `.github/workflows/deploy.yml` — `main`에 push되면 빌드 후 Pages 배포.

## 도구만 따로 배포하기

이 폴더는 "내 사이트 + 도구"가 함께 있다. 다른 사람에게 줄 도구만(내 책·설정 없이) 별도 저장소에 올리려면:

```
py tools/make_release.py                  # 무엇이 바뀌는지만 보기
py tools/make_release.py --push           # 배포용 저장소에 commit + push
py tools/make_release.py --push --tag v0.2.0   # GitHub 릴리즈까지
```

- 배포용 저장소 기본값은 `<내 아이디>/githubio_book` (`--repo 아이디/이름`으로 바꿀 수 있다).
- 작업 폴더에서 **먼저 commit** 해야 한다. 마지막 커밋(`HEAD`)에서 책(`docs/`의 책 폴더, `public/`),
  `books.json`, `sidebar.json`, `site.json`을 비운 사본을 만들기 때문에, 커밋 안 된 수정이나
  `config.json` 은 절대 섞여 들어가지 않는다.
- 사본에 내 아이디, 내 컴퓨터 경로, 내 책 이름이 남아 있으면 중단한다.
- 코드는 이 폴더에서만 고친다. 배포용 저장소는 이 스크립트가 만드는 결과물이다.

## 의존성

- Python 3 (tkinter 포함, 윈도우 기본 설치본이면 됨).
- git — GitHub 에 올릴 때 필요.
- pandoc — **도쿠위키 소스를 쓸 때만** 필요 (`winget install pandoc`).
- 로컬 미리보기(선택): `npm install` 후 `npx vitepress dev docs`.
